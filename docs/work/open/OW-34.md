# LRU subprocess cap N=16 (D12).

`src/server/http/session-manager.ts`

At attach, before spawning the 17th subprocess, evict the coldest eligible
session (LRU recency = last attach, held on `ManagedSession`), then spawn. Evict
via canonical ref (`#lookup`/`canonicalRef`). **All-busy = immediate reject:**
if all 16 are exempt, fail the attach with an at-capacity error rather than
waiting — deliberately visible. `maxSessions`/`idleTimeoutMs` are named
constants at the top of the module (no env, no config file).

## This path already announces itself — keep it that way (added 2026-08-28, for OW-lepoki)

Eviction here happens inside `attach`, before the spawn, and `attach` already calls `this.broadcaster.sessionsChanged()` once `pending.promise` resolves (`session-manager.ts`, just after `await pending.promise`).
That re-list is what corrects the evicted session's `status` in every connected client, so this card needs no broadcast of its own — unlike OW-33's timer, which has no such umbrella and must emit for itself.

Note the dependency rather than leaving it to be rediscovered.
It holds only while the eviction stays inside the attach flow ahead of that emit; move it to a background sweep or an early return and the stripe OW-lepoki (open) draws on attached rows will keep claiming a subprocess that is gone.
The all-busy rejection path is worth a thought here too: it fails the attach before that emit, which is correct, since nothing was evicted.

## Amended 2026-09-28 under D25

D25 in `docs/DESIGN.md` withdrew D12's transparent re-attach and declined OW-35, so an eviction under this cap is a visible close, as Detach is, and the evicted session comes back only through a deliberate attach.
The mechanism above is unchanged.

## Noted 2026-09-29: OW-bulanu landed

The `close()` this card evicts through now does all of its synchronous work before its first await: it flags and retires the startup from `#attaching` and `container.starting` through the one `#retire`, removes parked fork entries, and registers one `#disposing` entry that also carries any parked handle's disposal, including when there is no container.
An attach after an eviction therefore starts afresh instead of joining a torn-down startup, and `disposeAll()` now waits on every in-flight `#disposing` entry, so an eviction still killing its adapter holds shutdown until the kill completes.
