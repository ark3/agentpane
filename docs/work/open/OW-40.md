# No way to start a session in a workspace that has no existing sessions.

`src/client/App.svelte`

OW-39 replaced the free-form workspace input with a dropdown derived from the
listed sessions, and `New session` inherits the selected session's cwd — so a
brand-new workspace path can no longer be typed, and on an empty corpus `New
session` is disabled with no way to create the first session at all.
**Deprioritized to a deferral, by the project owner on 2026-08-14: the
workaround is to run `pi` or `codex` from the command line once in the new
directory, after which it appears in the dropdown like any other.** Do not build
an affordance for this without asking. Two corrections to the original row, both
checked at the source, kept only so a future revisit does not repeat the work:
(1) its constraint "must not reintroduce OW-3's per-keystroke enumeration" is
**misdirected** — OW-3's enumeration lived in `setWorkspace`, which OW-39
deleted outright, and filtering is now purely client-side over `sortedSummaries`
(`App.svelte:86-88`); a path input feeding only `controller.create` contacts the
server once, on click, so plain text entry is not the hazard the row implied.
(2) Whatever affordance is ever added must also close a server-side gap it would
make reachable: `POST /api/sessions` (`app.ts:165-170`) validates `cwd` as a
non-empty string and nothing more — despite its own error text reading "must be
an absolute path" — then `createVirtual` stores it unchecked and it reaches
`spawn(..., { cwd })` (`pi/process.ts:157`) only at first attach, so a typo or
relative path would return `201 Created` and surface as a spawn failure much
later. That gap is unreachable today precisely because `cwd` is always inherited
from a listed session. Surfaced in review of OW-39; read from the resulting UI,
not observed live.

**Re-confirmed as a deferral by the owner on 2026-08-19**, with everything
above checked still true at the source: `workspaceOptions` is derived from the
listed sessions (`App.svelte:153`), `newSessionWorkspace` is
`selectedSummary?.cwd ?? null` (`:180`) -- inherited from the *selected
session*, not even from the filter dropdown -- and `createSession` returns
early when it is null (`:694`). The server-side gap is unchanged at
`app.ts:166`.

One change since filing: there are now **two** blocked entry points, not one.
OW-72 added the tools-menu "New conversation" entry (`App.svelte:700-707`),
which inherits the selected session's workspace *and* backend and is gated on
the same null. The constraint got more visible without getting worse.

## Amended 2026-10-01 by OW-geselo

Read at b758f98: the server-side gap above is gone, and the limitation is now the browser's alone.

`createSession` in `src/server/http/app.ts` rejects a cwd that is not absolute ("cwd is required and must be an absolute path") and one that does not `stat` as a directory ("cwd must name an existing directory"); both came in 1eb66d4 on 2026-09-10 (OW-yeboje).
So correction (2) above, and the line numbers it cites, no longer describe the code: an affordance would make nothing invalid reachable.

The browser is as described, with one widening: `newSessionWorkspace` in `src/client/App.svelte` is `selectedSummary?.cwd ?? null`, `createSession` returns early without it, and the New button is `disabled={!newSessionWorkspace}`, so New is disabled whenever nothing is selected, not only on an empty corpus.
The Workspace `<select>` (`workspaceOptions`) only filters the list, and there is no free-form path entry; the Tools menu's `New conversation` (`newConversation`) reuses the selected session's cwd and backend.

The Emacs client already has the capability: `agentpane-new-session` in `emacs/agentpane.el` creates in `agentpane--current-cwd`, the buffer's project root or else `default-directory`, so it starts a session in a directory with none.
Under "Both clients" in `AGENTS.md` (set 2026-09-23, after the 2026-08-14 and 2026-08-19 deferrals above), this is a browser parity gap, and whether that overrides the owner's "do not build an affordance for this without asking" is the owner's call.
