# Prompting a detached/reaped session must transparently attach-then-submit, so D12 eviction is invisible.

`src/client/controller.ts`

When idle/LRU (OW-33/34) has reaped a session's subprocess, a prompt to it must re-attach before submitting rather than fail.
Verify the controller's current behavior first.
Since OW-tewave landed on 2026-09-16 the client does call the `DELETE` route, from a Detach item in the composer's Tools menu.
That does **not** make this card's scenario reachable, which OW-tewave's own text got wrong and OW-jamoyi corrects: after a detach the preview loads, `previewing` goes true, and `src/client/App.svelte` replaces the whole composer with a single Attach button, so there is no prompt box from which to prompt a detached session.
The path from that screen is `api.attach`, not attach-then-submit.
The one way the normal flow arrives here is a *failed* preview, which leaves `view.preview` null and the composer drawn over a session the client has dropped -- an error path, not the scenario.
So this card still waits on the reaper (OW-33/34), or on a second client detaching a session out from under this one (OW-fihuma's case), and it is still only the re-attach path, not any button removal.
Constraint for the D12 implementer: keep the `DELETE` route — it is programmatically useful and shutdown-adjacent code relies on it.
