# The transcript shows model and token count but never *when* a message happened, though every message already carries the timestamp.

`UserMessage`, `AssistantMessage`, and `ToolResultMessage` each carry
`timestamp: number` (epoch-ms) from pi-ai; the render path already holds it and
simply never displays it. Show an **absolute** timestamp, formatted **exactly**
like the session list's — reuse `App.svelte`'s `formatTimestamp` (ISO to the
second, UTC, deterministic regardless of the viewer's timezone;
`App.svelte:398`), which for that reason must **move to a shared module** both
call (a small date util, or `render/types.ts`), de-duplicating rather than
copying. One signature nuance: `formatTimestamp` today takes an **ISO string**
(`summary.updatedAt`), but message timestamps are **epoch-ms numbers**, so the
shared version must accept a number (or the message callers wrap via `new
Date(ms)`); keep the session-list call working unchanged. **Absolute, not
relative** — no ticking re-render, chosen deliberately. Three placements: (1)
**assistant** — add a time span to the existing `.meta` row beside model/tokens
(`Message.svelte`); this part is independent of OW-63 and could land alone. (2)
**user** — user messages have no meta row today; the timestamp shares the
per-block action row that **OW-63 introduces** (copy/expand under user content),
so **this row is sequenced after OW-63** and must not build that chrome itself.
Note the time is a *message-level* fact placed alongside *block-level* buttons —
fine because a user message is effectively one text block, but do not attach it
to a block as if it were block data. (3) **tool** — in the tool card's
**expanded body** (the native `<details>` body, not the collapsed summary line,
and not OW-63's fullscreen overlay). **Codex caveat, not a bug:** Codex
synthesizes message timestamps at turn granularity (`turn.startedAt * 1000`,
else `now()` — `src/server/adapters/codex/reducer.ts:139`), so every message in
a Codex turn shows the *same* time and it is second-coarse; that is expected, do
not "fix" it. Load-bearing: absolute and byte-identical to the session-list
format via a shared formatter; all three placements; tool time in the card body
not the summary; after OW-63 for the user placement. Incidental: exact span
position within a row, separator glyph. Done when tests assert the assistant
meta row renders the formatted time, the tool card body renders it while the
collapsed summary does not, and the shared formatter produces identical output
for an epoch-ms input and the equivalent ISO input (pinning the reuse); the user
placement is verified once OW-63's row exists.
