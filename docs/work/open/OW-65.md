# The session list is unlabeled, loose, gives no sign of which sessions are attached, and can only be re-listed by reload.

Four small changes to the left column, which is a CSS grid whose areas stack
`masthead` / `controls` / `sessions` / `prompt` (`app.css` ~line 118). (1)
**Label it.** The workspace and backend sections carry `<label>`s; the session
list (`.sessions`) does not. Add a `Sessions` header above the scroller. It must
be a **sibling above** `.sessions`, not inside it -- `.sessions` is
`overflow-y:auto`, so a heading placed inside would scroll away. This means a
new grid row/area (e.g. `sessions-header`) between `controls` and `sessions`.
(2) **Compact the rows.** Shrink `.session-preview` toward `--ap-text-sm`,
tighten `.sessions` gap and `.session-select` padding, and stop `.session-meta`
from wrapping (drop its `flex-wrap: wrap`) so a row stays one logical line
however long the cwd -- the fixed-height-row intent is already stated in
`app.css`'s comment above `.session-preview`; extend it to the meta line. Goal
is more rows visible at once; exact sizes are incidental. (3) **Show attached.**
`SessionSummary.status` is already `"virtual" | "detached" | "attached"` and
already on every rendered summary, but the list ignores it (it renders only the
`isStreaming` `●`). Boldface the backend-name span when `status === "attached"`
-- one `class:` binding plus one CSS rule. This is specifically "holds a live
subprocess," distinct from the streaming dot and from the viewed-row
`aria-pressed` styling; do not conflate them. (4) **Refresh button.** A small
control in the new header calling the existing `controller.refreshSessions()`
(already exposed, already wired to `listSessions` off disk). Its whole reason: a
session created from the CLI outside this app emits no `sessions-changed`, so it
never appears until a re-list. Browser reload already fixes this (reload re-runs
`controller.start()` -> `refreshSessions()`), so the button is a convenience
that avoids the reload's session-only-state reset, not a capability gap;
**server-side directory watching for an always-live list is explicitly out of
scope here** (name it, do not build it). Load-bearing: the label/refresh live
outside the scroll container; attached uses `status`, not `isStreaming`.
Incidental: exact font sizes, paddings, icon, header layout. Done when
`App.test.ts` asserts an `attached` summary renders the attached styling while a
`detached` one does not, and that the refresh control invokes `refreshSessions`;
compactness is a manual/visual check.
