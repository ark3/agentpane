# Sessions can be neither starred nor hidden, so the list is stuck with recency and never sheds anything.

`src/server/http/` (new store, plus a route in the per-session switch in `app.ts`), `src/shared/protocol.ts` (`SessionSummary`, `ServerEvent`), `src/client/session-state.ts`, `src/client/App.svelte`

Two needs, both the owner's, both stated on 2026-08-18. A long list has no
durable cue for the sessions worth returning to. And forking -- once it exists
(OW-mewiga) -- multiplies sessions, so the list accumulates conversations that
are known dead and cannot be put out of sight.

**The decision is D13 in `DESIGN.md`**; read it rather than this paragraph for
why the store is server-owned, why one three-state field instead of two flags,
and why a corrupt file is reported rather than logged. This item is what to
build. Note that this supersedes the entire previous body of OW-66, which
specified a per-viewer `localStorage` set and deferred pending exactly the
question D13 has now answered.

## What has to exist

- **A server-owned store.** Today the server writes nothing of its own -- there
  is no `writeFile`, `mkdir` or `appendFile` anywhere in non-test
  `src/server/`. This is the first, and D13 fixes its location, format,
  write discipline and failure behaviour. The store's directory must be
  injectable; without that, every server test writes into a real home directory.
- **A route to toggle a mark.** `src/server/http/app.ts` already dispatches
  per-session commands through one switch -- `fork`, `fork-points`, `model`,
  `compact` -- and this belongs beside them, not in a new shape.
- **The mark on `SessionSummary`** (`src/shared/protocol.ts:75-87`), because
  D13 has the client filtering rather than the server. A "show hidden" control
  needs the rows in hand either way.
- **A `notice` arm on `ServerEvent`.** Every error event today carries a
  `session` ref and a per-session `seq` (`broadcaster.ts:124`), and a corrupt
  state file belongs to no session. The precedent is exact: `sessions-changed`
  (`protocol.ts:174`) is already a session-less, seq-less arm, reduced as an
  early return at `session-state.ts:70`. Render it distinctly from `view.error`,
  which is per-session and sits by the session controls.

## The constraint that will bite

**No mark on a `virtual` session.** A session renames on its first prompt (D9:
`virtual:…` to a real backend id), so a key placed before that strands and the
store quietly accrues orphans. Forbidding the mark until `status !== "virtual"`
sidesteps migration entirely. `controller.onRename` -- which `App.svelte`
already uses to re-key its scroll and follow maps -- is the escape hatch if that
limit ever proves too strict. **Name it, do not build it.**

Records whose session has vanished from disk are left alone. Pruning needs a
"really gone?" judgement, and the records are bytes.

## Load-bearing versus incidental

Load-bearing, all from D13: the store is the server's, the field is one
three-state value with absent meaning normal, no mark on a virtual session,
temp-file-plus-`rename` on write, the client filters, and an unparseable file is
renamed aside rather than overwritten.

Incidental, decide in flight: whether starred rows float to the top of the list
or are merely drawn distinctly, the banner wording, the route's exact spelling,
and where the "show hidden" control sits.

Out of scope: anything that sets a mark automatically. D13 places the store so
that it *could* be done server-side and deliberately does not decide it.

## Done when

Five tests, each watched red first.

1. A server test pointed at an injected state directory toggles a mark, builds
   a fresh store over the same directory, and finds the mark still there.
2. Marking a `virtual` session is refused, and the client renders no mark
   control for one.
3. An unparseable state file is renamed aside rather than overwritten, the
   store comes up empty, and a `notice` event is emitted. Assert on the
   surviving file and the event, not on wording.
4. A client test asserts a hidden session is absent from the rendered list and
   present once hidden sessions are shown.
5. A client test asserts a `notice` event renders somewhere other than the
   per-session `view.error` banner, and that a session snapshot does not clear
   it -- the interaction OW-1 is open about for the per-session case.

`bun run check` passes.
