## What has to exist

- **A server-owned store.**
  It is the first agentpane state the server writes, and D13 fixes its location, format, write discipline and failure behaviour.
  Its directory is injectable; without that, every server test writes into a real home directory.
- **A route to set a mark**, in the per-session switch of `src/server/http/app.ts` beside `fork`, `model` and `compact`, not in a new shape, followed by `sessions-changed` so both clients re-list; and its method on the API in `src/client/api.ts`, which the Emacs helper calls too (`createAgentpaneApi` in `src/emacs/helper.ts`).
- **`mark` on `SessionSummary`**, absent for normal, because D13 has the client filtering rather than the server.
- **A session-less arm on `ServerEvent`** reporting a corrupt store.
  Every per-session event carries a `session` ref and a `seq`, and a corrupt state file belongs to no session; `sessions-changed` is the precedent for a session-less, seq-less arm.
  `notice` is taken, by the per-session backend notice whose docblock in `src/shared/protocol.ts` already says D13's arm is a different thing, so this one takes another name; that docblock and the one at "Not D13's session-less `notice` arm" in `src/server/adapters/codex/adapter.ts` then name it.
  Every reader of `ServerEvent` that narrows past `sessions-changed` and `ended` to `event.handle` has to narrow past it too: `reduceServerEvent` in `src/client/session-state.ts`, the two sites in `src/client/controller.ts`, and both `const { handle } = event` in `src/emacs/helper.ts`.
  The shared reducer carries the notice where both clients read it, `ClientState` or the reduce result, which this card picks, so OW-zewiru and OW-hahuna only draw it.
  The store is read at server start, before any client connects, and `broadcaster.ts` replays only live handles' snapshots (`sendOpeningSnapshots`), so the server holds the notice and sends it to every client as it connects; an event sent once at start would reach nobody.
- **The Emacs helper's half**: a JSON-RPC method to set a mark beside `sessions/setModel`, and a notification carrying the session-less arm, so agentpane-mode can show it.
  Both change the contract the `src/emacs/protocol.ts` docblock declares frozen, so the docblock records the raising, and its `sessions/list` entry, which lists the summary's fields, gains `mark`.

## The constraint that will bite

**No mark on a session that is not on disk.**
A session's ref changes at its first prompt (D9: `virtual:…` to a real backend id), so a key placed before that strands and the store quietly accrues orphans.
D13 forbids a mark on a `virtual` session, but a client cannot see that: `#liveOverlay` in `src/server/http/session-manager.ts` reports any session with an adapter as `attached`, a created one still unprompted among them.
D27 therefore takes `onDisk` as the rule both the route and the clients follow, which also covers a fork born without a file: the route refuses a session whose `onDisk` is false, which sidesteps migration entirely.

Records whose session has vanished from disk are left alone.
Pruning needs a "really gone?" judgement, and the records are bytes.

## Load-bearing versus incidental

Load-bearing, all from D13: the store is the server's, the field is one three-state value with absent meaning normal, no mark on a virtual session, temp file plus `rename` on write, the client filters, and an unparseable file is renamed aside rather than overwritten.

Incidental, decide in flight: the route's and the new arm's spelling.

Out of scope: anything that sets a mark automatically, which D13 places the store to allow and deliberately does not decide; D27 leaves hiding forks automatically deferred on the same footing.
