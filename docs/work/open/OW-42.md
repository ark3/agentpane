# App tests still substitute a non-publishing controller at the re-entrancy boundary where production has already failed once.

`src/client/App.test.ts`, `FakeController` and `PublishingPreviewController`; `src/client/controller.ts`, `createController`, `preview`, `create`, `select`, and `abort`; `src/client/controller.test.ts`; closed OW-41 and OW-detepa.

OW-41 proved the failure mode: 605 green tests missed a startup infinite loop because `FakeController.preview` recorded a call while the real controller published synchronously and re-entered a Svelte effect.
The one-off `PublishingPreviewController` pins that incident, but `FakeController` remains the dominant App test seam and still does not model the publish timing of `create`, `select`, or `abort`.
OW-detepa independently reached the same conclusion for render-cost work and built a publishing test controller because the existing fake could not exercise the behavior under test.

Do not make `FakeController` grow another partial imitation of production.
Add a small jsdom integration band that renders `App.svelte` with the real `createController` and a deterministic fake `AgentpaneApi`, reusing or extracting the fake-api patterns from `src/client/controller.test.ts`.
Keep ordinary component tests on `FakeController`; use the integration band only for flows where a controller publish can re-enter an App effect or where ordering between busy, selected, preview, and error state matters.

Cover the remaining original seams: create a session through the UI and converge on its attached selection exactly once, select and attach a stored session without an older intent winning late, and abort a streaming selected session while the real controller publishes its busy transitions.
Each regression should assert the API call count and the final controller and App state, not reproduce implementation-specific intermediate wording.
If one of these flows already has equivalent real-controller coverage, cite the exact test and omit the duplicate; this card closes on the integration band, not on a quota of three tests.

Done when at least one new test is shown red by replacing the real controller with the old non-publishing fake or otherwise removing the relevant publish, all retained flows pass through `createController`, and `bun run check` is green.
This work is deliberately not labelled `browser-testing`: the browser UI suite and OW-24 cover different boundaries, while this fast jsdom band exists to keep controller and App re-entrancy in the ordinary check.
