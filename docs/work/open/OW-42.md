# `FakeController` does not publish the way the real controller does, so re-entrancy bugs pass its tests.

`src/client/App.test.ts`, `src/client/controller.ts`

OW-41 closed this gap for `preview` only, by way of
`PublishingPreviewController`; `create`, `select` and `abort` still diverge from
`controller.ts` on when they publish, so the same class of defect can still land
green. Separately, `controller.preview`'s synchronous `publish({ error: null })`
before the `await` is a standing hazard for any future effect keyed off
`state.selected` — OW-41 converged around it rather than changing it, because
clearing the error only on resolve changes when a stale error leaves the UI.
Decide whether to make the fakes publish like the real controller across the
board, or to reorder that publish. Related: OW-24 — there is still no broader
browser/integration coverage of the preview/create/select/abort paths through
the real controller — is the other half of why OW-41 went unobserved. Surfaced
while landing OW-41; not independently reproduced beyond `preview`.
