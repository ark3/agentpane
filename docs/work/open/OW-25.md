## Amended 2026-09-29, at OW-letevu's close

This card first asked whether Pi raises approval dialogs when its `trust.json` does not already trust the workspace, because `docs/HANDOFF.md` finding 42 was measured with one copied in and so showed only that the sandboxed path does not add a prompt.
OW-letevu retired the reason that mattered: D2a in `docs/DESIGN.md` now cancels every Pi dialog the moment it arrives and names it in a session error, so a dialog an untrusted workspace raises is loud where it arrives rather than a turn hung behind one line of text.
Finding 42's own run already had no `trust.json` to copy — the home server has none, which `docs/MANUAL_TESTING.md`'s "Two of the five files the probe copies do not exist here, including `trust.json`" records — and its tool turn raised no dialog on `pi 0.85.1`.

What is left is whether the copy itself still earns its place.
