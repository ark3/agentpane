`e2e/follow.spec.ts`; `e2e/harness.ts`, `runTurn`, `FollowHarness.seed`, `FollowHarness.metrics`; `src/client/App.svelte`, `reading`, `armFollow`, and `reconcile`; `src/client/render/transcript.ts`, `condense`.

OW-51 preserved original transcript indices so condensing cannot strand follow mode's `[data-index]` anchor, and OW-reyale proved in jsdom that Reading view shows, hides, and restores tool and thinking chrome for both live and stored transcripts.
Neither test can settle the interaction this card names because toggling changes the transcript's real height while follow is armed, and jsdom has no layout, scroll anchoring, `ResizeObserver`, or browser scroll-event timing.

The old instruction to wait for OW-24 is obsolete.
The synthetic Playwright harness has grown from OW-47's one-defect probe into the browser UI suite, and this deterministic layout interaction belongs there rather than in the production-server vertical slice.

Extend `e2e/follow.spec.ts` or add one focused sibling spec using the existing contracting turn shape: attach, seed enough completed turns to scroll, submit a paced turn, toggle Reading view on and back off while the turn is streaming, then let the turn settle.

If the current behavior fails, fix only the follow/reconcile interaction the browser exposes; do not move browser geometry into jsdom or couple this to OW-24's server work.
