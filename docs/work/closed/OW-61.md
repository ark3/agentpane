# Assistant-turn metadata shows model but drops Codex reasoning effort, so the transcript cannot display the effort level beside the model name.

`src/client/render/Message.svelte`, `src/server/adapters/codex/adapter.ts`, `src/server/adapters/codex/reducer.ts`, `src/server/adapters/types.ts`, `resources/codex-protocol/v2/Thread{Start,Resume}Response.ts`

The agreed scope is deliberately narrow: when effort is present, render it
alongside the model in the assistant-turn meta; when absent, omit it with no
placeholder. Do not chase mid-session settings churn — this UI does not let the
owner change model or effort, so capturing the value on attach/start is enough.
Pi's RPC protocol exposes no corresponding field, so this is expected to be
Codex-only.

**Fixed** in `72f744f`. The row's paths held up; `src/server/adapters/types.ts`
needed no change and was not touched. The type problem the row did not name:
`AssistantMessage` comes from `@earendil-works/pi-ai`, which D10 makes
types-only, and it has no effort field — so the value rides `AssistantTurn
extends AssistantMessage { effort?: string }` plus `PaneMessage =
Exclude<AgentMessage, AssistantMessage> | AssistantTurn`, both in
`src/shared/protocol.ts`. Because `effort` is optional the two are mutually
assignable, which is what kept the change surgical: the reducer, `AdapterState`
and the broadcaster all still say `AgentMessage`, and only the construction site
(`mapping.ts:assistant()`) and the render site (`Message.svelte`'s prop) name
the wider type. `Exclude` rather than a hand-written union so
`CustomAgentMessages` declaration merging still reaches it — `Message.svelte`'s
final `{:else}` depends on that openness.
`ServerEvent.snapshot.messages`/`upsert.message` were widened too: additive and
non-breaking, but D11 makes that file where the wire is stated and the field
genuinely rides the payload. Named `effort`, not `reasoningEffort`, because
Codex uses both for the same concept (`reasoningEffort` on the responses,
`effort` on `ThreadSettings`). One `setIdentity` call in `adapter.ts` covers
start and resume because both response types carry `reasoningEffort` identically
— OW-8's resume-typed-as-start assertion needed no touching, and the `hydrate`
path shares `remap`, so a resumed turn is stamped too. Both present-case tests
were re-verified red by the session agent after cherry-pick review, not just
reported: `expected [ 'example-model', '52 tok' ] to include 'high'`
(`Transcript.svelte.test.ts`, jsdom) and `expected undefined to be 'high'`
(`reducer.test.ts`, node). The absent cases pass trivially, so the executor
broke the omission logic — stamping `ctx.effort ?? "unknown"` and rendering the
span unconditionally — and watched those go red too. `bun run check` green on
`main` (634 tests). Not yet seen in a browser against a live Codex turn; the
presentation verdict is the owner's. Noted, not changed:
`ThreadIdentityResponse` (`reducer.ts:385`) has no references anywhere in
`src/`, pre-existing dead code left in place with its `Pick` widened to stay
accurate.
