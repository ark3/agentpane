# Repo/local file references in markdown are rendered as ordinary links even though agentpane has nowhere useful to send them.

The sanitizer hook in `markdown.ts` treats every non-`#` anchor as an external
link (`target="_blank"`), so references like `src/client/api.ts:35` become
clickable, fall into the SPA static handler, and effectively reload the app — a
false affordance that also drops context, since the rendered label can collapse
to the file name while hiding the line suffix. The agreed fix is deliberately
not a file viewer: detect local/repo file references, preserve `path:line` in
the visible text, style them distinctly from prose, render them as non-link
inline references so text selection keeps working. Real `http(s)` links remain
real links.

**Fixed** in `721193f`. The row's premise needed one correction, established by
probing `marked` 16.4.2 with this module's own options before dispatch: **bare
paths in prose are not autolinked** — `see src/client/api.ts:35` renders as
plain text — so the defect is only anchors from *explicit* markdown links, and
no source-side regex over prose was needed. `[api.ts](src/client/api.ts:35)` was
the motivating case: label collapsed, line suffix hidden in the href. Also note
the symptom was a *new tab* loading the app, not a reload of the current one,
because the hook stamped `target="_blank"`. The fix is a `link` override on the
private `Marked` instance beside the existing `code` override, emitting `<span
class="ap-file-ref">`; returning `false` hands every other href back to marked's
default renderer, so the anchor path to DOMPurify is untouched. Classification
is narrow on purpose — no URI scheme at all, or `file:` — because "anything not
http(s)" would take `javascript:`/`data:` out of DOMPurify's hands and break
`markdown.test.ts`'s "drops javascript: hrefs but keeps the link text". Visible
text is the location unless the author's label already contains it, which leaves
`[src/a.ts:5](src/a.ts:5)` verbatim and expands a collapsed label. No existing
test was edited. The four local-reference cases were re-verified red by the
session agent after cherry-pick review, not just reported (`expected <a
href="src/client/api.ts:35" ...> to be null`); the two control cases — web URL
stays a hardened link, in-document and hostile hrefs stay anchors — cannot go
red first by construction and exist to pin non-regression against exactly that
widening. `bun run check` green on `main` (640 tests).
`src/server/http/static.ts` was in the row's Where and was **not** touched: its
SPA fallback is gated on `Accept: text/html` and is correct for a real
navigation; the fix removes the navigation instead. Two recorded judgements,
neither reversed: the styling (monospace, `--ap-fg-muted`, dotted underline, no
accent) is a first cut awaiting the owner's verdict; and a protocol-relative
href (`[x](//example.com/y)`) has no scheme, so it is now rendered inert — `//`
is a scheme-relative URL by RFC 3986 but also a valid POSIX path, no case has
been observed in a transcript, and the failure mode is a link becoming
unclickable rather than anything unsafe, so no special case was encoded. Not yet
looked at in a browser; the presentation verdict is the owner's.
