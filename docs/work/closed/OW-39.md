# Split workspace browsing from session attach/create.

`src/client/App.svelte`, `src/client/controller.ts`, `src/client/api.ts`

The current free-form `Workspace` box does two jobs at once: it filters the list
(`setWorkspace` on every keystroke, OW-3) and it supplies `create(cwd, backend)`
for `New session`; selecting a row also attaches immediately, so merely browsing
sessions starts agents. Replace that with a recency-sorted workspace dropdown,
default `ALL`, derived from the listed sessions; the backend dropdown does not
participate in filtering. Selection becomes cheap: on startup and whenever the
workspace filter changes, auto-select the most recent session in scope; clicking
an existing row loads OW-38's read-only preview immediately, without attach. In
preview state, replace the composer with a full-width `Attach` button; clicking
it uses the existing attach path, swaps in the prompt box, and focuses it. `New
session` should inherit the currently selected session's workspace and remain an
immediately promptable new-session flow — do not create a preview-only
intermediate state for new sessions. This is the actual product issue behind
OW-3, OW-29, and the "future workspace-dropdown item" note in closed OW-30. Done
when: failing-first client tests show row selection no longer calls `attach()`
for stored sessions, startup/filter changes reselect the most recent in scope,
`New session` uses the selected session's workspace, and clicking `Attach` opens
the live session and leaves the prompt focused.

**Fixed** in `26d104f`, entirely in the client. `api.ts` gains `preview(ref)`
(GET `ROUTES.preview`, no body). `controller.ts` adds a `preview: { ref, turns
} | null` field to `ControllerView` and a `controller.preview(ref)` that loads
OW-38's read-only preview for a stored session (or reselects a session this
client already holds a live view for, no re-fetch); `applyAttached` nulls the
preview on an explicit attach; `setWorkspace` and the `workspace` var are
removed and `refreshSessions` always lists the whole corpus (retiring OW-3 at
the source). `App.svelte` replaces the free-form input with a workspace
`<select>` (default "All workspaces", sentinel `__all__`) derived from listed
sessions, filters the list client-side, auto-selects the most recent in scope on
startup and on filter change (via `controller.preview`, so no spawn), renders
preview turns as plain role-labelled `Markdown` (read-only, no live-parity
claim), and swaps the composer for a full-width `Attach` button in preview state
that runs the existing attach path then focuses the prompt. `New session`
inherits the selected session's cwd and is disabled with none (closes OW-29).
Pinned by failing-first tests in `api.test.ts`, `controller.test.ts`, and
`App.test.ts`: row click previews and does not `attach()`; startup and
filter-change reselect the most recent in scope; `New session` uses the selected
workspace; `Attach` opens the live session and leaves the prompt focused.
Fail-first re-confirmed in review — reverting the row handler to
`controller.select` turned exactly the "previews instead of attaching" test red
and only that one. `bun run check` green (605 tests). Subsumes OW-3 and OW-29;
the new-workspace/empty-corpus gap this design creates is filed as OW-40. No
live browser run (OW-24).
