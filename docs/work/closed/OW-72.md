# Nothing in Agentpane can compact a session's context; add a tools menu under the composer that does, on both backends, alongside a new-conversation entry.

Typing `/compact` into the composer sends the literal string to the model —
observed live against Codex (owner, 2026-08-18). No slash handling exists
anywhere in the stack: the draft goes `App.svelte:550` `submitPrompt` →
`controller.ts:259` `submit` → `api.prompt` → `adapter.submit(text)`, verbatim,
for both backends. OW-73 covers warning about the typed form and OW-74 is the
larger question of what command surface Agentpane should have; **this item is
the menu and its two entries**, and must not answer OW-74.

## The menu

A tools popup under the composer at the **left** end of the `.prompt` form —
`Send`/`Abort` sit right, in `.prompt-actions` (`App.svelte:705`). Owner's
decision, this session. It ships with two entries, **New conversation** and
**Compact**, both acting from the selected session.

**The existing New button stays** (`App.svelte:603`); the menu entry is an
addition, not a move (owner, this session). They are not redundant, because the
button is *configured* and the menu entry is not. `createSession` (`:536`) reads
the workspace select (~588) and the backend select (`:598`) that sit directly
above the button, which is how you start a session on a different workspace or
backend from the one you are reading. The menu entry has neither select beside
it, so it means **"another conversation like this one"**: same workspace and
same backend as the selected session, inheriting both. Workspace already
inherits (OW-39); backend inheriting is the new part. With nothing selected
there is nothing to inherit, so the entry is disabled — as the button already is
when `newSessionWorkspace` is unset.

Inheriting both was confirmed by the owner on 2026-08-18, as was disabling the
entry with nothing selected — with the note that the second case "never
happens", so spend a line on it and no more. It is reachable in principle: the
composer is gated only on `previewing` (`App.svelte:695`), so the form renders
with no session selected, and `controller.submit()` already answers that state
with "Select a session before submitting a prompt." (`controller.ts:262`) rather
than preventing it. Disable the entry and move on; do not build a story around
it.

The container is not built for two entries. Two more capabilities are already
finished server-side with no client surface at all: `GET /api/models` is served
at `src/server/http/app.ts:73` and `BackendAdapter` has `setModel`/`listModels`,
yet nothing under `src/client/` ever calls it — there is no model picker; and
`submit(text, images?)` accepts `ImageInput[]` with no way to attach one. **Do
not build either here.** They are named so the menu is not designed as a
one-off, not as scope.

## Invoking it

Codex has `thread/compact/start`, params `{ threadId }`, response an empty
object. Verified against the installed `codex-cli 0.147.0` on 2026-08-18 with

    codex app-server generate-json-schema --out <dir>

which writes `v2/ThreadCompactStartParams.json` and
`v2/ThreadCompactStartResponse.json`. It is in the default bundle, not only
under `--experimental`. Compaction runs as a turn that refuses steering —
`NonSteerableTurnKind` is `["review", "compact"]`, and app-server pushes
`activeTurnNotSteerable` for a `turn/steer` sent during one. So check what the
adapter's own `TURN_ACTIVE_ERROR` guard (`codex/adapter.ts:69`) does while a
compaction turn is live, and decide deliberately whether `submit()` is refused
then rather than discovering it.

Pi's command name is **not known**. `pi/protocol.ts:12` records that compaction
knobs "are all real commands we simply never send", so one exists; `PiCommand`
does not list it. `pi` is not installed on the authoring laptop, so nobody has
read it. Verify at the source before writing the type, against
`pi-coding-agent/docs/rpc.md` and the installed CLI's
`dist/modes/rpc/rpc-types.d.ts` — the same two references `pi/protocol.ts`'s
own header names.

`BackendAdapter` in `src/server/adapters/types.ts` is marked FROZEN, "raise it
before editing". It was raised and **the owner approved adding a required
`compact()` to it on 2026-08-18** — required rather than optional, because both
backends have the capability and nothing is forced to fake it. Adding a method
is the case that note guards least, since no existing caller changes, but say so
in the commit, and add the matching HTTP route and `src/shared/protocol.ts`
entry alongside `prompt`/`abort`.

## Showing it

Pressing Compact must change the transcript, or the control is indistinguishable
from a no-op. Today it would not:

- **Codex drops it.** `contextCompaction` is `{ type, id }` and nothing else,
  and `codex/reducer.test.ts:901` asserts it reduces to `[]`. The item carries
  no summary text, so the Codex rendering can only be a marker — do not go
  hunting for a summary the protocol does not have. The older `thread/compacted`
  notification is deprecated in the schema in favour of this item, so build on
  the item.
- **Pi is unverified and may already be worse than nothing.** `compaction_end`
  is handled at `pi/reducer.ts:118` for its `errorMessage` only. But if Pi
  pushes a `compactionSummary` message through `message_start`/`message_end`,
  the reducer appends it like any other message (`:68`), and `Message.svelte`'s
  final `{:else}` renders an unrecognised role as a raw JSON dump in
  `.msg.unknown`. **First step: trigger a compaction on Pi and look at what the
  pane does**, before deciding what to build.

The message type needs no invention. pi-agent-core declaration-merges
`CompactionSummaryMessage` — `{ role: "compactionSummary", summary,
tokensBefore, timestamp }` — into `AgentMessage`
(`pi-agent-core/dist/harness/messages.d.ts`), which is what `DESIGN.md:546`
means by "Pi has a compaction message type; mirror it".

**One renderer, not two** (owner, 2026-08-18): it always draws the marker, and
draws the summary only when there is one. Codex therefore gets a bare marker
every time and Pi gets a marker with text, from the same component — so the
no-summary case is the normal path, not a fallback, and must read well rather
than look broken.

Load-bearing: the menu sits under the composer on the left; it carries both
entries; the existing New button survives; compaction works on **both**
backends; the transcript shows it afterwards. Incidental: the menu's looks,
whether it is a `<details>`, a popover, or a menu element, and how the marker is
worded.

## Done when

Testing here is fixture-driven and costs nothing: adapter and reducer tests
drive a fake process over recorded JSONL in `resources/fixtures/{codex,pi}/`,
and `e2e/` runs against a synthetic backend. **No compaction capture exists** —
the six fixtures are `text`, `tool-read` and `tool-edit` only — so this item has
to make one rather than hand-write a wire shape nobody has seen.

- A **captured** compaction fixture per backend is committed under
  `resources/fixtures/{codex,pi}/`, alongside its `.meta.json`, in the shape the
  existing six use. Recorded from a real run, not authored.
- A Codex adapter test drives the fake process and asserts the outgoing request
  is `thread/compact/start` carrying the adapter's thread id, and the matching
  Pi adapter test asserts whatever command the source says Pi's is.
- A render test feeds a compaction message to `Message.svelte` and asserts it is
  **not** the fallback card — `data-role` neither `unknown` nor absent — with a
  summary and without one.
- A client test asserts the menu's New conversation entry creates a session
  carrying the selected session's workspace **and** backend, and a second
  asserts the button at `App.svelte:603` still creates one from the two selects.
- `bun run check` passes.
- A paragraph in `MANUAL_TESTING.md` records the live run and the **measured
  drop in context tokens** across the compaction, per backend. This is the one
  claim a fixture cannot carry: a recording proves the request went out and the
  transcript rendered, never that the context actually shrank. The token figure
  the session already tracks (`Message.svelte:96`) is the before/after to quote.
