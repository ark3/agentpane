# Whether to import the generated bindings into `src/` or reference them in place.

`resources/codex-protocol/`

Either way they stay the source of truth; do not hand-write Codex types.

**Closed on 2026-08-19: already decided, and the decision is recorded at the
site.** The bindings are **referenced in place**, and
`src/server/adapters/codex/protocol.ts:1-18` carries both the choice and its
reasons: copying `resources/codex-protocol/` into `src/` would mean 642 files
to re-sync by hand every time Codex moves; every import is `import type`, so
nothing survives compilation and the tree never enters the bundle or the test
runtime; and `tsconfig.json` excludes `resources/` from its include globs,
which does not stop the program typechecking because exclude only filters
those globs and files reached by an import are still part of the program.

That module re-exports only what the adapter uses, so a Codex rename has one
place to be fixed. Read it there rather than here -- this note exists to
retire the question, not to duplicate the answer.
