# The transcript has no per-block actions — add side-by-side copy and expand affordances at the block level.

Copy and expand are one feature: they act on the same units, sit as sibling
buttons in the same per-block chrome, share machinery (expand's copy-all *is*
the copy helper), and edit the same files — so they land together, not in two
sessions where the second inherits a moved codebase and re-agrees the unit
boundaries the first already set. **Both operate on individual blocks, never on
a whole message.** An assistant message is an ordered mix of
text/thinking/toolCall blocks (`ContentBlock` in `types.ts`); concatenating
those into one "copy/expand the message" string was considered and rejected — it
would invent a serialization (how to render a toolCall as text?) and produce
something no single source ever held. The units are the blocks themselves: a
**fenced code block** (its raw `block.text`/code source, not the highlighted
HTML and not the fence's language tag), a **markdown text block** (its source
markdown), a **thinking block** (`block.thinking`), and a **tool result /
command output** (`resultText(message)` for a `toolResult`, the `Output.svelte`
`text` prop for command output). **Copy:** what reaches the clipboard is the
**source prop the component already holds**, not the rendered DOM — so it is
precise (only that block, no adjacent chrome like the tool name, status pill,
streaming cursor, or a truncation notice), it is the real bytes rather than the
browser's whitespace reconstruction of the layout, and it is **not limited to
what is rendered**. That completeness-and-precision over drag-selection is the
whole point of the button. Feedback is inline on the button: a brief ✓ on
success and ✗ on failure via a transient class/state, no global toast layer.
`navigator.clipboard.writeText` is the mechanism; guard for its absence
(undefined in jsdom and on a non-secure origin) rather than throwing.
**Expand:** opens a full-screen overlay showing that block's content large. It
is the app's first modal (none today — `App.svelte`'s only layered element is
`.jump-to-latest`, and errors render inline), so this introduces a small
reusable one. Hard requirements: (1) the body is **real, selectable text** —
click-and-drag selection plus the browser's own copy menu/hotkey must work, so
it renders actual sanitized content (reuse `renderMarkdown`/`renderCode` from
`markdown.ts`; never bypass the D5 sanitize choke point) and never a
`pointer-events:none` node; (2) a **copy-all button** in a corner copies the
whole block in one click, sharing the copy helper/feedback above; (3) a
**visible close affordance** — an X in a corner — plus **Esc**; (4) **no
dismiss-on-backdrop-click**, because a text selection that ends on the backdrop
would otherwise be read as a dismiss and lose the selection. On open, move focus
into the panel; restore it on close. The buttons themselves (copy/expand/close)
are excluded from both the selectable body and what copy-all copies. **No
images** on either action — image blocks and the image parts of a tool result
get no copy/expand control; text actions act on text. **Empty/redacted blocks
get no buttons** — a thinking block with no text (Pi emits these with an opaque
signature) has nothing to copy or expand, so the controls should not render.
Deliberately **read-only**: no edit/resubmit (blocked on OW-22). Load-bearing:
block-level not message-level; copy source not rendered DOM; expand body is real
selectable sanitized text with no backdrop-dismiss and explicit X + Esc; no
images; no controls when there is nothing to act on. Incidental: exact icons and
✓/✗ glyphs, button placement within each block's chrome, overlay
layout/animation, which file the overlay lives in. Done when a
vitest/testing-library test per block type asserts (a) clicking copy calls
`writeText` with the expected source string and a rejected write surfaces the
failure state rather than throwing; (b) opening expand renders a body carrying
that block's content, Esc and the X close it while a simulated backdrop click
does **not**, and copy-all writes the full source (mock the clipboard); and (c)
an empty/redacted thinking block renders neither control.

**Fixed** in 4464c74: `BlockActions.svelte` pairs `CopyButton.svelte` with an
expand button and renders `Expanded.svelte`, wired in at four places —
`Block.svelte` (text), `Thinking.svelte` (inside `{#if text}`, so
signature-only and redacted blocks get nothing), `Output.svelte`
(`source={text}`, not `clipped`, so copy and expand both carry the full body
past the 20000-char display cap), and `Markdown.svelte` (per fence). A fence
had no component to ask and `sanitize()` forbids `<button>`, so the `code`
renderer numbers each one `data-fence="N"` and `renderMarkdownWithFences`
hands back the raw sources; `Markdown.svelte` renders its own Svelte controls
into a hidden dock and an effect moves each next to its `<pre>`. The overlay is
`position: fixed; z-index: 50` — the app's first layered element — renders its
body through the same `Markdown`/`Output` components (so it stays behind the D5
sanitize choke point and is real selectable text), keeps its chrome in the
header, and closes on the X or Esc but never on a backdrop click. 19 tests in
`src/client/render/BlockActions.test.ts`, each watched red first by reverting
the line it covers: copying `preview` instead of `text` on thinking, `clipped`
instead of `text` on output, the highlighted body instead of the raw code on a
fence, dropping the `try/catch` behind both clipboard failures, adding
`onclick={onclose}` to the backdrop, hoisting the controls out of each
nothing-to-act-on guard. Review added the streaming case: a one-shot attach
passes the single-fence test and fails only once a second fence appears in a
later frame, and it corrected this file's sibling claim in `Markdown.svelte`'s
docblock — a moved control survives a re-parse because `{@html}` removes only
what it inserted, not because the effect re-runs. Deferred, not done: no focus
trap or scroll lock in the modal (OW-63 asked only for focus in and restore
out), and the presentation is a first cut — glyphs, 0.55-opacity chrome, and
the actions row below rather than inside each block.
