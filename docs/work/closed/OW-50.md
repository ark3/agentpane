# The read-only preview is a second transcript renderer, and it has already drifted from the first.

`src/client/App.svelte:545-561`, `src/client/app.css:185-198`, `src/client/render/Message.svelte:71`

`app.css:186-197` re-implements `Transcript.svelte`'s container plus
`Message.svelte`'s `.msg`/`.user`/`.who` rules with the same tokens and the same
values, and two divergences already exist: the preview labels both roles
("You"/"Agent", `App.svelte:551`) where the transcript labels only the user
(`Message.svelte:44,52`), and `.transcript` sets font-family, size, line-height,
colour and background (`Transcript.svelte:34-44`) where `.preview` sets none of
them and inherits. Fix it **client-side only** — the server keeps returning
`SessionPreviewTurn[]`. Do *not* widen `SessionPreviewResponse` to carry
`AgentMessage`s: that is a D11 frozen-interface change, and its Codex half needs
a whole second mapper, because stored rollout records are `response_item`
payloads rather than the `ThreadItem`s `mapping.ts` consumes. Instead map each
turn to a message-shaped object in the client, render it through `Transcript`,
and delete `App.svelte:548-558` and `app.css:186-197`. A synthetic assistant
message typechecks without lying about a provider: `Api` and `ProviderId` are
open unions, so `provider` and `model` carry the backend id (`pi`/`codex`) — the
owner's ask, since that is the one identity a preview genuinely knows — and
`api` a placeholder; `stopReason:"stop"` with zero usage suppresses both the
error banner and the token line. One consequence to handle: the meta line
renders only when `usage.totalTokens > 0` (`Message.svelte:71`), so the backend
id would never appear — split that condition. Keep `.preview-empty`'s wording.
**Success criterion: the preview and an attached session render the same DOM
structure for the same content.**

**Fixed** in `f7aa3ae`: a new pure `previewMessages(turns, backend)`
(`src/client/preview.ts`) maps `SessionPreviewTurn[]` to `AgentMessage[]` — user
turns pass straight through as `{role,content,timestamp}`, assistant turns carry
`provider`/`model` = the backend id, `api:"session-preview"`,
`stopReason:"stop"` and zero usage — and `App.svelte` renders the result through
the same `Transcript` the attached path uses. The bespoke markup and `app.css`'s
`.preview`/`.preview-turn`/`.preview-role` rules are gone, the now-unused
`Markdown` import with them; `.preview-empty` and its wording stay, rendered
*instead of* `Transcript` on zero turns rather than through it, because "No
messages yet" would misreport a session whose text-only extraction came up
empty. `Message.svelte`'s meta line is split so the model span renders whenever
there is a model and the token/cost spans only when there is usage, which also
unhides the model for a real turn reporting zero usage. `timestamp` is a
constant, not a clock read: it feeds only `keyFor`, which already carries index
and role, so a clock read would churn the `{#each}` key on every re-render.
Server untouched; `SessionPreviewResponse` unchanged. Pinned by three new tests,
all confirmed failing first: the success criterion itself (preview and attached
`.transcript` innerHTML identical for the same content — red as `expected
undefined to be truthy`, there being no `.transcript` on the preview path at
all), the labelling and backend attribution (red on finding `<span
class="preview-role">Agent</span>`), and the zero-usage model span (red as
`expected '' to contain 'example-model'`). The empty-preview wording test passes
trivially against the old code, so it was reproduced red by temporarily routing
the empty case through `Transcript`; that is recorded here rather than claimed
as a fail-first. **The row's guess that `App.test.ts` asserted on
`.preview-role`/`.preview-turn` was wrong** — nothing did, so there was coverage
to add and none to update. One incidental consequence, read from the cascade and
**not visually confirmed** (OW-55): the deleted global `.preview` rule was also
hitting `Thinking.svelte:58-59`'s collapsed summary span, which carries the same
class name and sets no `display`/`gap`/`padding` of its own. `bun run check`
green at 617 tests.
