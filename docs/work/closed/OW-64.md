# Tool output is truncated at 20000 characters for display, which is far tighter than the browser can comfortably render.

`Output.svelte` caps its rendered body at `limit = 20000` and shows an "Output
truncated (N characters)" notice past that. This is the *inline rendering* cap,
separate from what OW-63's copy/expand yield (those read the full source prop
regardless). The cap guards the genuinely unbounded channel — tool results, file
reads, ripgrep dumps, JSON args all flow through `Output.svelte` and none is
bounded by a model's output-token budget — but 20000 is needlessly small: the
accepted tradeoff (owner, this session) is that a large tool result rendering in
full inline is fine in a scrollable pane with collapsed cards. **Raise the
default `limit` to 250000.** Keep the truncation mechanism and the notice for
the genuinely-enormous case beyond that; this is a bigger ceiling, not its
removal. Note the two callers that already pass an explicit `limit` if any exist
(none today — every `<Output>` uses the default), so the constant change is the
whole change. Load-bearing: 250000, and truncation still exists above it. Done
when a test renders an `Output` body between 20000 and 250000 chars and asserts
it is shown in full with no truncation notice, and one above 250000 still
truncates.

**Fixed** in 258aaa4: `Output.svelte`'s `limit` default is 250000; truncation and the notice are unchanged above it. `src/client/render/tools/Output.test.ts` renders a 200000-char body and asserts `.clipped` is absent with the full text shown, and a 260000-char body still clips and names "260,000". Both were shown red first — the full-render test fails at `limit = 20000`, the truncation test fails at `limit = 10000000`. Two existing fixtures sized to the old cap (`BlockActions.test.ts` `longOutput`, `tools.test.ts` "clips output an agent could produce megabytes of") were resized to clear the new one. `Expanded.svelte` passes `limit={source.length}` and is unaffected — the item's claim that no caller passes an explicit limit was wrong on that one point.
