# Wrapping a spawn error loses the original stack, `code` and `cause`.

Pi process shell

The message survives; the identity does not.

## Close note

Absorbed by OW-sozopu.
The one process shell (`ChildProcessShell` in `src/server/adapters/child-process.ts`) keeps the spawn error, and a stdin error, as `cause` on the Error it hands its exit handlers, and `PiAdapter` passes that cause to the rejections of pending commands, so `start()`'s rejection on a failed spawn carries the original ENOENT (tests in `child-process.test.ts` and `pi/process.test.ts`).
Not done, and judged not worth a card: Codex's `CodexClient` (`codex/jsonrpc.ts`, its `proc.onExit` handler) rebuilds the error as `new CodexRpcError(cause.message)` and drops the cause again; clients receive `onError` as a string anyway, and nothing in production reads `.cause`.
