# OW-39's startup auto-select infinite-loops on a real page load

(`effect_update_depth_exceeded`); the app hangs on load whenever a stored
session exists. The auto-select `$effect` (App.svelte:362) calls
`controller.preview(top.ref)` while `view.state.selected === null`; the real
`preview` (controller.ts:219) publishes synchronously (`publish({ error: null
})`, line 227) *before* it awaits `api.preview`, which reassigns App's `view`
and re-invalidates the effect before the async resolve flips `selected` — so the
effect re-fires on its own publish, synchronously, until Svelte's depth guard
throws. The `workspace !== autoWorkspace` guard doesn't converge: the `else if
(selected === null && top)` branch (line 368) re-fires on every publish. **Why
605 green tests missed it:** `FakeController.preview` (`App.test.ts:100`)
records the call but never publishes, so the real re-entrancy can't occur under
test — the fake diverges from the real controller exactly on the looping
behavior, and OW-24 (no browser/integration test through the real controller)
left it unobserved until a live load. Intent: make auto-select converge
synchronously (e.g. track the ref already auto-previewed, not just the
workspace, so the guard clears before any re-run) while keeping OW-39's behavior
— auto-open the most recent in scope on startup and on filter change, no spawn.
Done when: a failing-first test reproduces the loop against a controller/api
that publishes like the real one (or renders `App` on the real
`createController` + a fake `api`) — throwing/looping before the fix, green
after — and App's existing OW-39 auto-select tests still pass. Regression in
closed OW-39 (`docs/CLOSED.md`); ids are not reused.

**Fixed** in `a06bb51`. The auto-select `$effect` now tracks `autoPreviewedKey`
— the `sessionKey` of the ref it already auto-previewed — alongside
`autoWorkspace`, and writes that guard *before* calling `controller.preview`.
The re-entrant run triggered by `preview`'s own synchronous publish then finds
the guard already satisfied and stops, so the effect reaches a fixed point
without waiting on the await. `controller.ts` was left unchanged. Evidence: the
new test `auto-selects exactly once when preview publishes before it resolves`
renders `App` against `PublishingPreviewController`, a fake whose `preview`
publishes synchronously with `selected` still null and resolves a microtask
later — run against the pre-fix `App.svelte` it fails with `Svelte error:
effect_update_depth_exceeded`, the same error the live page load produced, after
spinning for 17s; green after the fix. Both OW-39 auto-select tests pass
unchanged. `bun run check` green at 606 tests, up from 605. What this left open
is OW-42: the fix closed the fake-vs-real publish gap for `preview` only, and
deliberately did not touch `controller.preview`'s early `publish({ error: null
})`. Behavior narrowing worth knowing: with a per-ref guard, auto-select will
not re-fire for the same top-of-list ref within one workspace scope if
`selected` returns to null.
