# `suppressScrollHandling` is a boolean where the thing it guards can happen twice in one frame.

`src/client/App.svelte`, `pendingProgrammaticScrollTop`,
`classifyConversationScroll`, `applyScrollTop`, and `handleConversationScroll`

`applyScrollTop` arms it and `handleConversationScroll` consumes it, but scroll events dispatch asynchronously, so two programmatic
scrolls to *different* values landing before the first event arrives produce two
events against one flag — the second reads as a user scroll and disengages
follow for that turn. Two callers can assign in one frame: the frame-coalesced
message effect (`scheduleFollow`) and the unthrottled `ResizeObserver`.
The no-op guard in `applyScrollTop` closes the identical-value case only.
This was candidate (a) of OW-47 and is **not** what caused it; a counter-based
guard was written while chasing OW-47, measured to change no outcome, and
reverted rather than landed speculatively. The race was therefore read from the
source and remained unproven when this card was filed. The eventual browser
reproduction also showed why a counter is insufficient: Chromium may coalesce
multiple pre-delivery assignments into one event, leaving a count stale. The
landed classifier instead matches the latest programmed position at capture
time and marks the specific event. Surfaced while landing OW-47.

Reproduced the overlapping native-scroll delivery in headless Chromium: the boolean implementation cleared follow and left the submitted prompt 344.75px from its lock point. Added `rapid app-driven scrolls do not masquerade as a reader scroll` to `e2e/follow.spec.ts`; it failed before the fix and passes after it. Replaced assignment-count suppression with capture-time classification of the browser's latest actual programmed position, so a second assignment made during delivery remains pending for its own event while Chromium-coalesced assignments cannot leave stale suppression that swallows a reader scroll. The existing one-pixel manual-scroll case remains green. Verified with `bun run check` (47 files, 871 tests) and `bun run test:browser` (11 tests).
