# Selecting an existing session should be able to load a read-only transcript preview without attaching or spawning a subprocess.

`src/shared/protocol.ts`, `src/server/http/app.ts`, `src/server/sessions/pi.ts`, `src/server/sessions/codex.ts`, `src/server/sessions/index.ts`

Today the only per-session read path is `GET /api/sessions/:backend/:id`, and
the contract explicitly defines it as "open this session": `sessionRoute()`
calls `sessions.attach(ref)` before replying. Add a distinct non-attaching
preview path for stored sessions that reads the backend's JSONL on disk by ref
and returns a simplified conversation for the main pane. Keep the scope
intentionally narrow: text turns only, flattened for read-only display; skip
tools, thinking, images, approvals, and any claim of live parity. Preserve D9's
cheap-selection goal by reading **one session file**, not the whole corpus: for
Pi the ref is already the JSONL path; for Codex find the matching file by thread
id/filename rather than `list().find()`, reusing OW-23's constraint that a
targeted read must not parse every session in both stores. Done when:
failing-first server tests prove the preview route returns text for
representative Pi/Codex stored sessions, does not call `attach()`/spawn, and
leaves the existing attach route's spawn-on-open behavior intact.

**Fixed** in `a51b085`: new `GET /api/sessions/:backend/:id/preview` route
(`SessionPreviewResponse` = `{ ref, turns: { role:"user"|"assistant", text }[]
}`) reads exactly one stored file by ref and flattens its text turns, spawning
nothing — it goes through a new `SessionIndex.preview()` seam
(`deps.index.preview`) and never touches the `SessionManager`. Pi reads the ref
path directly (D9); Codex finds the one filename carrying the thread uuid via
`findJsonlFiles` (readdir-only), anchoring the id as the trailing name segment
so a longer id containing it as a substring does not false-match, then reads
only that file. Text turns only — tools/thinking/images/approvals dropped;
user-turn synthetic wrappers (`<environment_context>` etc.) filtered via
`isSyntheticBlock`. Pinned by `preview.test.ts` (unit, incl. "reads only the
matching file" via a counter seam), `app.test.ts` (route never attaches —
`attach` spy + `pi.created`/`codex.created` empty — and attach-on-GET still
spawns), and `composition.test.ts` (real filesystem walk end-to-end). Fail-first
confirmed by the executing agent and re-confirmed in review: injecting `attach`
into the route turned the 5 app preview tests red; a read-all-files variant
turned "reads only the matching file" red. Extractors additionally verified in
review against real `~/.pi` (11 alternating turns) and `~/.codex` (real user
turn, wrappers filtered) store files. `bun run check` green (598 tests). The
recorded `resources/fixtures/*` are RPC-stream captures, not the on-disk store
format these parsers read, so tests synthesize store-format JSONL inline,
matching the sibling parser tests. Client wiring is OW-39, not this row.
