# Put "New session" on the same line as the Backend selector, and shrink its label.

`.session-controls` (`App.svelte:438-456`) is a single-column grid
(`app.css:136`: `display: grid; gap: var(--ap-space-3)`), so the Workspace
`<label>`, Backend `<label>`, and the `New session` `<button>`
(`App.svelte:455`) each stack on their own line. Wrap the Backend label and the
button in a row container (flex, `align-items: flex-end` so the button lines up
with the `<select>`'s baseline rather than the "Backend" text label above it) so
they share one line; leave Workspace on its own line above. Shrink the button's
label from "New session" to "New" (or a "+" glyph with an `aria-label="New
session"` if going iconic — either satisfies the ask, pick one) — it doesn't
need to be a wide button once it's sitting next to the selector rather than
spanning the sidebar. `createSession`/`disabled={!newSessionWorkspace}`
(`App.svelte:397-399`, `455`) are unchanged; this is layout and label text only.
Done when: a client test asserts the button's accessible name is "New" (or "New
session" via `aria-label` if iconic) and it renders inside the same row element
as the Backend `<select>`.

**Fixed** in `c9798aa`: a `.session-controls-row` flex container (`display:flex;
align-items:flex-end`, with `flex:1` on its label so the select takes the
remaining width) wraps the Backend label and the button so they share one line;
Workspace keeps its own line above. The label is now "New" rather than an icon,
so the accessible name is "New" — the two existing tests that queried the button
by its old name were updated to match, asserting the same things. Pinned by a
new `App.test.ts` test that the button and the Backend `<select>` share a row
container, confirmed failing first (it could not find a button named "New"
against the pre-change markup). `bun run check` green at 609 tests. Note for
whoever reads the diff: the executing worktree was cut two commits behind `main`
and so did not contain OW-44; the changed regions did not overlap and the patch
applied cleanly, with `bun run check` re-run on `main` before the commit.
