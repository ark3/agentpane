# Drop the visible "You" label from user turns.

`src/client/render/Message.svelte:44`

The filled surface, accent left border and width cap (`Message.svelte:114-122`)
already mark a user turn as the reader's own; the word is redundant. Applies to
the preview too, which after OW-50 renders through this same component. **The
`<span class="who">` is currently the only role signal for assistive
technology** — `data-role` is not announced, the `<article>` carries no
`aria-label`, and assistant turns have no cue at all — so removing it leaves the
transcript role-less to a screen reader. **The project owner accepted that
explicitly on 2026-08-15**, recorded here so a future agent reads it as decided
rather than as a bug to helpfully fix. Revisit if anyone but the owner uses
this.

**Fixed** in `46f2c8a`: the span is gone, and with it the `.who` rule, which
existed only for it — grep across `src/` and `e2e/` confirms no other markup or
CSS referenced either. Pinned by a new `Transcript.svelte.test.ts` case
asserting a user turn renders no `.who` and no "You", confirmed failing first
against the unmodified component (`expected <span class="who
svelte-sbhkvv">You</span> to be null`). OW-50's preview test was updated rather
than deleted: its intent is that the preview labels turns exactly as the
transcript does, which now means *neither* role is labelled, so its "You"
assertion inverted and its name gained "(no role label)"; its backend-id
assertion is untouched. The executing agent proposed opening an `OW-` row for
the assistive-technology regression; deliberately **not** opened, because it is
not undone work — it is the decision this row records, and the trigger to
revisit it ("if anyone but the owner uses this") is stated above. No
`aria-label`, `role`, or visually-hidden span was added to compensate. `bun run
check` green at 618 tests.
