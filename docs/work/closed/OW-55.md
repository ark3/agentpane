# The collapsed thinking summary's ellipsis has never been verified in a browser after its accidental global styling disappeared.

`src/client/render/Thinking.svelte`, the `.preview` span and its scoped `overflow`, `text-overflow`, and `white-space` rules; `e2e/harness.ts`, the synthetic thinking turn; `e2e/`.

OW-50 deleted a global `.preview` rule that had accidentally laid out this unrelated span as a padded flex column, leaving the thinking component's scoped rule as the only styling.
The current rule intends one clipped line with an ellipsis, but that is a box-layout claim and no browser evidence has ever checked it.

The old requirement for a local model is obsolete.
The Playwright harness already creates deterministic visible thinking content for OW-47, so this can be settled without any provider exposing reasoning and without a live backend.

Expose or seed a completed assistant thinking block whose one-line preview is wider than the available transcript row, then assert in a focused Playwright test that the collapsed details stays on one summary line, the preview box remains within the summary and transcript width, and `scrollWidth > clientWidth` with computed `text-overflow: ellipsis`.
Open the details once as a control and assert the body remains available; the test is about collapsed preview geometry, not whether thinking content exists.
If Chromium shows the current class still lays out incorrectly, rename the generic `preview` class or add the smallest scoped flex constraint in `Thinking.svelte` and watch the geometry assertion go red before the fix.

Done when `bun run test:browser` contains the geometry assertion and it is shown to discriminate under a targeted style regression, `bun run check` passes, and the observed result is recorded in `docs/MANUAL_TESTING.md` under OW-55.

## Close note

Built `e2e/thinking-preview.spec.ts` with `seedThinking()` in `e2e/harness.ts`: a completed turn whose 80-character collapsed thinking preview outruns its row at the suite's 900x700 viewport (scrollWidth 593 against clientWidth 395).
The spec asserts the collapsed summary is one line high, the preview overflows with computed `text-overflow: ellipsis`, its box sits inside the summary and the pane, and `.conversation` does not scroll sideways; it then opens the details as a control and sees the body.
Chromium (headless shell 1234, Chrome for Testing 151) lays the scoped `.preview` rule out correctly as it stood, so `Thinking.svelte` did not change.
Discrimination: removing `white-space: nowrap` (summary 40.28px), `overflow: hidden` (pane scrollWidth 695 against 512) or `text-overflow: ellipsis` (computed `clip`) each turns the spec red; removing `min-width: 0` changes nothing, because `overflow: hidden` already makes the flex item's automatic minimum width zero.
`bun run test:browser` 28/28 and `bun run check` pass; the measurements are recorded in `docs/MANUAL_TESTING.md`, "Observed the collapsed thinking preview clipped to one line (OW-55)".
