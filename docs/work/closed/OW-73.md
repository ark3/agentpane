# A draft that starts with `/` looks like a command and is not one, and nothing says so until the model answers it.

Observed live against Codex (owner, 2026-08-18): `/compact` was typed, sent as
literal text, and answered as a prompt. Nothing in the stack inspects the draft
— `App.svelte:550` `submitPrompt` → `controller.ts:259` `submit` →
`api.prompt` → `adapter.submit(text)` — and a grep for slash handling across
`src/` finds none at all. Pi behaves identically; this is not a Codex quirk.

**Warn before submitting; never block.** When the draft starts with `/`, show a
warning by the composer saying Agentpane does not run slash commands and that
this will reach the agent as literal text. Send keeps working exactly as it does
today, and the warning is the whole of the change. Decided by the owner on
2026-08-18, who did not want real commands wired into the composer.

Because nothing is blocked, **no list of command names and no exact-match rule**
— an earlier draft of this item had both, and they only ever existed to avoid
wrongly refusing to send. A prompt legitimately starting with a path
(`/home/ark3/…`) will trip the warning, and that is fine and must stay fine: the
cost of a false positive is one line of text the reader ignores. Do not add
precision here; it buys nothing and it is the thing this item was already wrong
about once.

**It has to be pre-submit, which is the whole point.** After submitting, the
model's confused reply already tells you — what it does not do is give the turn
back. Fork would, and Agentpane has no fork: `listForkPoints`/`fork` are on the
adapter contract with routes at `src/shared/protocol.ts:239` and `:247`, and
nothing under `src/client/` calls either. So a mis-sent draft costs a real turn
in both directions and cannot be rewound, and a warning that arrives after the
send is worth nothing.

By the composer rather than in the existing `.error` banner (`App.svelte:641`),
which sits up by the session controls, is fed by `view.error`, and carries
session errors — a note about the text you are typing belongs next to the text
you are typing. Load-bearing: pre-submit, advisory only, triggered by a leading
`/`, rendered near the textarea. Incidental: the wording, and whether it names
the tools menu OW-72 adds.

## Done when

A client test sets the draft to `/compact` and asserts the warning is shown
*without* submitting anything; a second asserts submitting it still calls
`api.prompt` with the text unchanged; a third asserts an ordinary draft shows no
warning. Watch all three fail first. `bun run check` passes.

**Fixed** in df6e19d: `App.svelte` derives `looksLikeSlashCommand` from `view.draft.startsWith("/")` — a bare leading-`/` check, no command list, no trimming — and renders a `<p class="warning">` inside the `.prompt` form above the textarea. `submitPrompt` and `handlePromptKeydown` are untouched, so Send and Ctrl/Cmd-Enter behave exactly as before. Three tests in `App.test.ts`: a `/compact` draft shows the warning with `controller.submitted` still 0, submitting it calls submit once with the textarea value unchanged, and an ordinary draft shows nothing. Only the first goes red against the unmodified app — the other two hold trivially without the feature, since this is purely additive; they are regression guards against a later blocking implementation, not proof of absence. Review changed the copy from `--` to a real em dash: this is user-visible text, and the rest of the UI writes Unicode (`…`).
