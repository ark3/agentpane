# A "reading view" toggle that elides tool calls, tool results and thinking blocks, for scrolling back through a session while it is still running.

Add a pure `condense(messages)` beside `buildTranscript` (`transcript.ts:45`)
that drops `toolResult` messages and `toolCall`/`thinking` blocks and keeps user
and assistant text. Keep each entry's *original* index so follow mode's
`data-index` anchor still resolves (`App.svelte:219`); the anchor is always a
user message (`App.svelte:340`), which condensing never elides, so OW-47's
scroll work is untouched. Decisions, all taken with the project owner on
2026-08-15: **the name is "reading"**; **one global boolean, not persisted, not
per-session**; **the control goes in `.session-controls`**; **scroll position
may jump when toggling** and pinning is not wanted yet; **the toggle stays
visible and inert while previewing**; **hiding thinking blocks is a first cut,
not a settled decision** — the owner wants to use the feature before deciding.
No liveness cue is needed: the Abort button renders only while streaming and the
sidebar row carries a ●.

**Fixed** in `f0459b6`: `condense(view: TranscriptView): TranscriptView` takes a
*built* view rather than raw messages, which is what makes the index constraint
hold by construction — filtering entries preserves `TranscriptEntry.index`,
where mapping over `messages` and re-deriving position would renumber everything
after an elision and strand the follow anchor. `Transcript.svelte` gains a
`reading` prop; `App.svelte` gains `let reading = $state(false)` and a
`aria-pressed` toggle in `.session-controls`, which needed no CSS — the existing
global `button[aria-pressed="true"]` rule already styles it. Nothing in the
scroll path was touched. Keys are preserved on surviving entries, so toggling
updates the DOM in place rather than rebuilding it. **One decision beyond the
row, taken by the executing agent and worth knowing:** assistant turns that
condense to zero blocks are dropped (else they render an empty article, or a
bare cursor if streaming), **except** a turn whose `stopReason` is `error` or
`aborted` — those already carry empty `content` today and their entire payload
is the banner, which is not tool chrome, so a blanket drop would have made
reading view silently swallow "Aborted." and provider errors. The streaming
`pending` placeholder is still dropped, so there is no bare cursor. Both halves
are one line and one test to reverse. Pinned by 12 new tests. Fail-first was
done in the strong form: rather than one red run, the agent broke `condense` six
separate ways and recorded which test caught each — re-deriving index from
condensed position (red on `[0,1]` vs expected `[0,3]`, the follow-mode
assertion), keeping toolCall/thinking blocks, keeping empty entries, keeping
tool results, mutating `message.content` in place, and dropping the `{reading}`
prop and the button. `bun run check` green at 630 tests; `bun run test:browser`
re-run on `main` after the merge, green (`e2e/follow.spec.ts`, 29.2s). Reviewed
and rejected as a blocker: dropping the streaming tail shifts `lastIndex` to an
already-finished entry, which then renders with `streaming=true` — but that flag
only drives `Markdown`'s frame throttle and the empty-content cursor, and a
finished message's text does not change, so there is no visible consequence. Two
gaps left open as OW-56.
