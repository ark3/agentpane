# D7. Sandbox spawn: the server does it, no wrapper scripts

The server spawns `direnv exec <workspace> sbox -- <agent> ...` directly.
One seam, no PATH dependency, testable.
The workspace is also the process's real cwd, not only an argument, because sbox finds its workspace from the cwd and argv alone jails the wrong tree (`src/server/adapters/pi/spawn.ts`); a session with no recorded workspace is refused rather than spawned anywhere (`session-manager.test.ts`).
`~/.local/bin/sandboxed-pi` exists for pipane specifically and is not used here.
